# 開発規約・コーディングガイドライン

## ブランチ戦略
GitHub Flowを採用しています。

- `main`：本番環境に対応するブランチ。直接pushは禁止
- `feature/xxx`：機能開発用ブランチ
- `fix/xxx`：バグ修正用ブランチ
- `hotfix/xxx`：緊急の本番障害対応用

## プルリクエストのルール
- レビュワーは最低1名の承認が必要
- CIがすべてグリーンであること
- PR本文にはテスト方法・影響範囲を記載すること
- 自分でマージするのは原則禁止（緊急時はリーダー承認が必要）

## コミットメッセージ
Conventional Commitsに従ってください。

```
feat: ユーザー認証機能を追加
fix: ログインページのバリデーションエラーを修正
docs: READMEのセットアップ手順を更新
refactor: 認証ミドルウェアをリファクタリング
```

## コードレビューの観点
1. 動作の正確性
2. セキュリティ上の問題がないか
3. パフォーマンスへの影響
4. テストが書かれているか
5. 命名・可読性

## テスト方針
- 単体テストのカバレッジ目標：80%以上
- PRにはテストコードを必ず含める
- E2Eテストは主要フローのみ対象

## デプロイフロー
1. PRマージ → stagingへ自動デプロイ
2. QAチームの確認
3. リリース承認後 → 本番へデプロイ（毎週火・木 15:00）
